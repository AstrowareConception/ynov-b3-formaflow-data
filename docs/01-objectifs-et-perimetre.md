# Objectifs et périmètre

## Capacités travaillées

Le dépôt doit permettre d'analyser un besoin, de construire et éprouver des modèles de données, d'exécuter un schéma PostgreSQL, de mesurer quelques choix physiques et de comparer plusieurs familles NoSQL à partir de leurs accès et garanties.

Le résultat attendu n'est pas un système complet. L'étudiant doit surtout apprendre à relier :

- une règle à une représentation ;
- une représentation à une contrainte ;
- une hypothèse à un protocole ;
- une mesure à un contexte ;
- un choix technologique à un coût et une limite.

## Éléments fournis

- corpus FormaFlow figé ;
- briefs et scénarios ;
- données synthétiques ;
- schéma relationnel volontairement fragile ;
- requêtes et besoins de reporting ;
- gabarits de décision et de modélisation ;
- protocoles de mesure ;
- traces préparées pour les moteurs NoSQL trop coûteux à exécuter ;
- commandes et checkpoints de reprise.

## Éléments construits par les étudiants

- glossaire ciblé et questions ouvertes ;
- MCD, MLD et MPD ;
- contraintes, index et requêtes ;
- analyse des dépendances fonctionnelles ;
- décision de dénormalisation ;
- quatre modèles NoSQL minimaux ;
- matrice comparative et benchmark borné ;
- architecture polyglotte et stratégie de synchronisation ;
- trace individuelle CDAN.

## Hors périmètre

- développer une API ou une interface utilisateur ;
- administrer un cluster de production ;
- faire fonctionner quatre moteurs NoSQL simultanément ;
- construire un data lake, un entrepôt industriel ou une plateforme temps réel ;
- figer les bounded contexts du futur module DDD ;
- évaluer la maîtrise d'un outil de diagramme particulier.
